# Шаблоны вывода

Два режима: **markdown в чате** (дефолт) и **HTML-артефакт** (по триггерам).

---

## Markdown — базовый формат

```
Я проверил: данных достаточно, начинаю анализ

## UX-аудит
Иконки: 💰 деньги | ⛔ ошибки | 🤔 непонятно | 🐢 долго | ✨ всё хорошо

| Тип | Эвристика | Проблема | Риск | Критичность | Что сделать |
|---|---|---|---|---|---|
| ⛔ | 5. Предотвращение ошибок | Пользователь может..., потому что..., из-за чего... | Потеря данных | 🔴 Высокая | Конкретное действие |
| 💰 | 1. Видимость статуса | ... | Снижение конверсии | 🟠 Средняя | ... |
| ... | ... | ... | ... | ... | ... |
| ✨ | 9. Помощь при ошибках | Проблем не выявлено | — | 🟢 Нулевая | — |

**Общая оценка:** N%
**Главный риск:** одна фраза
**Что исправить в первую очередь:** одна фраза

---
Что дальше:
- Закинь ещё экраны — расширим разбор сценария
- Пришли доработанный вариант — сравним до/после
- Углубиться в конкретную эвристику
- Сделать чек-лист до релиза
```

**Правила markdown-таблицы:**
- Колонка «Тип» — **только иконка** без слова. Расшифровка в легенде сверху
- 10 строк = 10 эвристик
- Если по эвристике всё хорошо — строка остаётся с `✨ Всё хорошо`, `🟢 Нулевая`, риск и действие — `—`
- Пиши кратко: 1–3 предложения на клетку «Проблема», 1–2 на «Что сделать»

## Markdown — серия экранов как сценарий

> **Важно:** если экранов 2+, по умолчанию переходи на HTML-режим (см. ниже) — там превью с подписями. Markdown с серией экранов используй только если дизайнер явно сказал «без файла» или «коротко».

```
Я проверил: данных достаточно, начинаю анализ
Сценарий: [короткое описание потока в 1 строку]

## UX-аудит
...

| Тип | Эвристика | Проблема | Риск | Критичность | Что сделать |
|---|---|---|---|---|---|
| ⛔ | ... | На шагах 3–4 пользователь может..., потому что..., из-за чего... | ... | 🔴 Высокая | ... |
| 💰 | ... | На шаге 2 ... | ... | 🟠 Средняя | ... |

**Общая оценка:** N%
...
```

Если одна проблема повторяется на нескольких шагах — пиши её один раз с диапазоном шагов. Не описывай каждый экран отдельно.

## Markdown — данных недостаточно

```
Я проверил: данных недостаточно — [конкретно чего не хватает].

Чтобы провести аудит, нужно:
- [пункт 1]
- [пункт 2]

Анализ не начинаю. Когда соберёшь данные — пришли в этот чат.
```

**Когда останавливаться:**
- Нет экранов вообще
- Непонятно, что за продукт и какой сценарий
- Прислали один скрин кнопки без контекста с просьбой «оцени интерфейс»

**Когда продолжать с ограничением:**
- Есть экраны, но не указан профиль пользователя → допустим «массовый пользователь продукта»
- Есть экраны, но не указана платформа → определи по визуалу
- Один экран вместо сценария → анализируй один экран, укажи ограничение

## Markdown — частичные данные

```
Я проверил: данных достаточно, начинаю анализ
Ограничение: [что именно ограничивает анализ]

## UX-аудит
...
```

**Примеры ограничений:**
- «прислан один экран, переходы и контекст сценария не анализируются»
- «нет указания платформы, оцениваю по визуальным признакам как iOS»
- «не указан профиль пользователя, допускаю массовую аудиторию»

## HTML-артефакт — когда и как

**Триггеры на HTML:**
- Экранов 2+ (автоматически)
- Запрос на сравнение или чек-лист (автоматически)
- Фразы: «оформи», «сохрани», «отправь», «передать», «PDF», «JPEG», «документом», «отчёт»

**Триггер на режим «без скринов»:**
- «без превью», «без скринов», «NDA», «безопасный режим», «конфиденциально»

### Структура JSON для скрипта сборки

```json
{
  "title": "UX-аудит",
  "meta": "Авито · кабинет продавца · модалка · десктоп · 1 экран · профи-продавец",
  "screens": [
    {
      "path": "/mnt/user-data/uploads/screen1.jpg",
      "caption": "Экран 1: модалка «Все результаты»",
      "subcaption": "Аналитика объявления Fujifilm X100VI"
    }
  ],
  "figma_links": [],
  "no_screenshots": false,
  "legend": "Иконки: 💰 деньги | ⛔ ошибки | 🤔 непонятно | 🐢 долго | ✨ всё хорошо",
  "rows": [
    {
      "type_icon": "🤔",
      "heuristic": "6. Узнавание",
      "problem": "Пользователь может не понять...",
      "risk": "Откладывание правок",
      "criticality": "🟠 Средняя",
      "action": "В каждом пункте показывать..."
    }
  ],
  "score": 84,
  "main_risk": "Рекомендации не показывают текущее состояние",
  "first_priority": "В каждой рекомендации показать текущее значение и цель"
}
```

### Запуск скрипта

```bash
python3 /path/to/skill/references/build_audit.py \
  --data /tmp/audit-data.json \
  --template /path/to/skill/references/html-template.html \
  --output /mnt/user-data/outputs/ux-audit-<name>.html
```

После — `present_files` с путём к HTML.

### Что скрипт делает сам

- Уменьшает скриншоты до 1100 px по ширине, сжимает JPEG до 82%
- Кодирует в base64 и встраивает в HTML
- Если скринов нет (`no_screenshots: true`) — блок превью содержит только текстовые имена экранов
- Если есть Figma-ссылки — рендерит карточки-ссылки
- Собирает строки таблицы
- Добавляет дисклеймер про base64-скрины в подвал (только если есть встроенные скрины)

## Пример заполненного аудита (markdown)

Сценарий: модалка аналитики объявления в Авито, десктоп, 1 экран.

```
Я проверил: данных достаточно, начинаю анализ
Ограничение: прислан один экран, переходы не оцениваются

## UX-аудит
Иконки: 💰 деньги | ⛔ ошибки | 🤔 непонятно | 🐢 долго | ✨ всё хорошо

| Тип | Эвристика | Проблема | Риск | Критичность | Что сделать |
|---|---|---|---|---|---|
| 🤔 | 6. Узнавание | Пользователь может не понять, что именно нужно изменить и насколько, потому что рекомендации не показывают текущие значения («Дополните описание минимум 30 символами» — сколько сейчас?), из-за чего откладывает действия | Откладывание правок | 🟠 Средняя | В каждом пункте показывать текущее значение и дельту до цели: «Описание: 12 из 30 символов» прямо в карточке |
| 🤔 | 1. Видимость статуса | Пользователь может не понять, по сравнению с чем считается «↑20%» и почему «57%» подсвечены красным, а «67%» — нет, потому что нет подписи периода сравнения, из-за чего динамика читается как случайные цифры | Недоверие к метрикам | 🟡 Низкая | Добавить под цифрами период сравнения и единое правило цветового кодирования с легендой в тултипе |
| 🤔 | 2. Реальный мир | Пользователь может не понять, что такое «цена просмотра» и «уровень сервиса», потому что это внутренние термины Авито без раскрытия, из-за чего боится трогать рекомендацию | Отказ от продвижения | 🟡 Низкая | Под термином давать одну строку объяснения или показывать пример эффекта |
| 🤔 | 10. Справка | Пользователь может не получить ответ на возникающие вопросы в контексте, потому что у рекомендаций нет инлайн-подсказок, из-за чего уходит в саппорт за тем, что можно объяснить одной фразой | Лишние обращения в саппорт | 🟡 Низкая | Добавить иконку «?» с тултипом у ключевых терминов |
| ✨ | 3. Свобода и контроль | Проблем не выявлено | — | 🟢 Нулевая | — |
| ✨ | 4. Консистентность | Проблем не выявлено | — | 🟢 Нулевая | — |
| ✨ | 5. Предотвращение ошибок | Проблем не выявлено | — | 🟢 Нулевая | — |
| ✨ | 7. Гибкость | Проблем не выявлено | — | 🟢 Нулевая | — |
| ✨ | 8. Эстетика | Проблем не выявлено | — | 🟢 Нулевая | — |
| ✨ | 9. Помощь при ошибках | Не оценивается — нет состояний ошибок | — | 🟢 Нулевая | — |

**Общая оценка:** 84%
**Главный риск:** рекомендации не показывают текущее состояние → пользователь может проигнорировать карточку целиком
**Что исправить в первую очередь:** в каждой рекомендации показать текущее значение и цель прямо в карточке. Один паттерн закроет три из четырёх проблем

---
Что дальше:
- Закинь экран после клика по «Уровень сервиса 53% → Подробнее»
- Пришли мобильный вариант — сравним
- Пришли доработанный вариант — сделаю до/после
- Углубиться в блок «Увеличение просмотров»
```

**Что важно в этом примере:**
- Все 10 эвристик в таблице, включая «всё хорошо»
- Сортировка: 🔴 → 🟠 → 🟡 → 🟢, внутри — по типу влияния
- Проблемы — гипотезы, а не утверждения
- «Риск» в 1–3 слова, не повторяет гипотезу
- «Что сделать» — конкретное действие
- Главный риск — не самая частая проблема, а самая опасная

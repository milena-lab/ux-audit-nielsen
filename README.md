## Что это

Claude Skill, который проводит UX-аудит интерфейса по **10 эвристикам Якоба Нильсена**. После установки активируется автоматически, когда вы просите оценить дизайн, найти UX-проблемы или сравнить варианты концептов.

Принимает на вход скриншоты, ссылки на Figma или текстовое описание — выдаёт структурированный разбор с приоритизацией проблем по критичности и конкретными рекомендациями.

## Зачем

- **Структурированный аудит** вместо разрозненных замечаний — все 10 эвристик проверяются за один проход.
- **Гипотезы о пользователе**, а не утверждения о дизайне («пользователь может…, потому что…, из-за чего…»).
- **Приоритизация по критичности** — сразу понятно, что чинить первым, а что можно отложить.
- **Готовый артефакт** для отправки команде или клиенту — с превью, таблицей, выгрузкой в PDF/JPEG.

## Возможности

- ✅ Аудит одного экрана или серии экранов
- ✅ Параллельное сравнение 2–4 концептов с градацией преимущества
- ✅ Два формата вывода: markdown в чате (быстро) и HTML-артефакт (с превью)
- ✅ Кнопки скачивания PDF (многостраничный A3) и JPEG прямо в артефакте
- ✅ NDA-режим — HTML без встроенных скриншотов для конфиденциальных продуктов
- ✅ Гибридная рекомендация — «возьми структуру из 1, плотность из 2»

## Использование

### Триггер-фразы

| Запрос | Пример | Результат |
|---|---|---|
| Аудит экрана | «Проведи UX-аудит этого экрана» | Markdown-таблица в чате с 10 эвристиками |
| Серия экранов | «Разбери сценарий покупки» (3+ скрина) | HTML-артефакт с превью каждого шага |
| Сравнение | «Сравни концепты» (2+ скрина) | HTML-артефакт с параллельной таблицей |
| Сохраняемый отчёт | «Оформи документом» | HTML-артефакт с кнопками PDF/JPEG |
| NDA-продукт | «Аудит без скринов в файле» | HTML без встроенных изображений |

### Что можно передавать

- 📸 **Скриншоты** (PNG, JPEG) — основной формат
- 🎨 **Ссылки на Figma** (требуется экспорт ключевых экранов в png)
- 📝 **Текстовое описание** интерфейса — рабочий, но ограниченный вариант

## Технические детали

### Markdown vs HTML

По умолчанию ответ идёт **markdown в чате** — это дёшево, безопасно и подходит для большинства случаев. На **HTML-артефакт** скилл переходит автоматически при:
- 2+ экранах в одном запросе
- сравнении концептов
- явной просьбе «оформи / сохрани / отправь»

Скрипты сборки HTML (`build_audit.py`, `build_compare.py`) принимают JSON с данными аудита и собирают артефакт из шаблона. Это снижает расход токенов в ~3 раза — Claude генерирует только содержательную часть, а CSS/JS/разметка уже готовы в шаблоне.

### Подсчёт оценки

Каждая эвристика даёт вклад в общую оценку в зависимости от критичности:

| Статус | Вклад |
|---|---|
| 🟢 Нулевая (всё хорошо) | +10% |
| 🟡 Низкая | +7% |
| 🟠 Средняя | +3% |
| 🔴 Высокая | +0% |

Максимум 100%. В сравнении оценки считаются для каждого концепта отдельно — победитель получает 10% по эвристике, проигравший минусуется по критичности.

### Экспорт в PDF и JPEG

В HTML-артефакт встроены две кнопки. PDF собирается через `html2canvas` + `jsPDF` как многостраничный A3 landscape. JPEG — снимок страницы с белой рамкой 24 px вокруг контента.

Кнопки работают и в Claude.ai preview, и в скачанном HTML, открытом локально — используют `pdf.output('blob')` + `<a download>` (обходит ограничение sandbox Claude.ai, где стандартный `pdf.save()` блокируется CSP).

## Разработка

### Клонировать и собрать скилл локально

```bash
git clone https://github.com/milena-lab/ux-audit-nielsen.git
cd ux-audit-nielsen

# Для упаковки в .skill понадобится скрипт package_skill из Claude skill-creator
# (входит в комплект Claude.ai при создании скиллов)
```

### Использовать скрипты сборки отдельно

```bash
pip install Pillow

# Одиночный аудит
python3 references/build_audit.py \
  --data examples/audit-data.example.json \
  --template references/html-template.html \
  --output ./my-audit.html

# Сравнение
python3 references/build_compare.py \
  --data examples/compare-data.example.json \
  --template references/html-template-compare.html \
  --output ./my-compare.html
```

Это удобно для CI-пайплайнов или массовой генерации отчётов из JSON-данных, без участия Claude.

## Методологическая база

Скилл опирается на две устоявшиеся методологии в области UX-исследований:

### Эвристики юзабилити — Nielsen Norman Group

Используются **10 эвристик Якоба Нильсена** с официальными определениями NN/g (статьи на [nngroup.com](https://www.nngroup.com/articles/ten-usability-heuristics/)). В файле [`references/heuristics.md`](./references/heuristics.md) для каждой эвристики:
- Точная цитата официального определения NN/g
- Ссылка на оригинальную статью
- Список типичных нарушений в дизайне
- Правила «не путать с» — какие близкие эвристики не дублировать

### Классификация UX-проблем — Markswebb

Используется методология выявления и квалификации UX-проблем от агентства **[Markswebb](https://markswebb.ru/)**. Из неё взяты:
- **Принцип «UX-проблема = состояние пользователя»** — проблема существует только тогда, когда её испытывает пользователь, а не как «свойство интерфейса само по себе»
- **4 уровня критичности** (от Нулевой до Высокой) с критериями приоритизации
- **Расширенная классификация из 12 категорий** способов воздействия UX-проблем — для углублённого разбора, когда базовых 5 типов влияния не хватает

Расширенная классификация описана в [`references/classification.md`](./references/classification.md) с маппингом 12 категорий → 5 базовых типов.
